# КОРУС · Пространство развития

Рабочее desktop-first приложение HR-ассистента на React + TypeScript + Supabase.

## Что реализовано

- вход по логину и паролю без подтверждения почты;
- динамический список тестовых аккаунтов на входе, включая вновь созданных сотрудников;
- профиль по кликабельному аватару, Telegram, выход и светлая/тёмная тема;
- сворачиваемое до иконок меню и корпоративная градиентная оболочка;
- динамические связи `HR` и `руководитель` без постоянной роли руководителя;
- ИПР по разделам, предложения задач, согласование и самооценка выполнения в процентах;
- официальный и личный календарь, приглашения, принятие/отказ и запросы на перенос;
- список сотрудников HR, переназначение связей, создание и удаление аккаунтов;
- список команды руководителя и ИПР подчинённых;
- отдельные личные и групповые чаты, непрочитанные сообщения, выход и управление участниками;
- именованные шаблоны опросов, три аудитории, история ответов и регулярное расписание;
- внутренние уведомления и обновление в реальном времени;
- загрузка, просмотр, скачивание и адресное предоставление документов;
- полезные ссылки с теми же уровнями доступа, редактированием и удалением.

## Тестовые аккаунты

Доступные тестовые пользователи загружаются из базы и показаны на экране входа. Нажатие на карточку безопасно подставляет данные в форму. Пароли и пары доступа не хранятся в репозитории.

## Локальный запуск

```bash
pnpm install
cp .env.example .env
pnpm dev
```

В `.env` нужны только публичные параметры:

```env
VITE_SUPABASE_URL=https://PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=PUBLIC_KEY
```

Секрет `service_role` не попадает в браузер: аккаунты создаёт функция `k-employee-admin` на стороне Supabase. Для первичной инициализации демонстрационной среды пароли передаются функции через секрет `KORUS_DEMO_PASSWORDS_JSON`.

## База данных

Проект использует отдельные таблицы с префиксом `k_`, поэтому не пересекается с таблицами приложения «Пульс команды». SQL находится в [supabase/migrations](./supabase/migrations), функция управления аккаунтами — в [supabase/functions/hr-admin](./supabase/functions/hr-admin).

Все клиентские таблицы защищены Row Level Security. Главный HR работает со всеми сотрудниками; обычный HR — со своими; руководитель — со своими подчинёнными; сотрудник — со своими данными. Базовые профили доступны как корпоративный справочник, а ответы коллег скрыты от оцениваемого сотрудника.

## Проверка

```bash
pnpm run build
```

TypeScript и production-сборка проходят без ошибок. Страница входа и динамический список тестовых аккаунтов проверены в Chrome; схема данных, закрытое хранилище и Edge Function развёрнуты в Supabase.

## Осознанные границы прототипа

- корпоративный SSO и календарь КОРУС пока заменены Supabase Auth и внутренним календарём;
- интеграция с корпоративным календарём КОРУС запланирована после получения API/регламента;
- бронирование переговорных оставлено на следующий этап;
- напоминания за неделю показываются внутри приложения; системные push-уведомления потребуют отдельной корпоративной настройки;
- перед реальным использованием нужны корпоративная политика персональных данных, аудит действий и усиленные требования к паролям.
